# 03. 사실과 Insight를 보존하는 글쓰기
Blog Context를 1차 입력으로 사용한다. 학습 배경·가설·사고 모델 변화·실제 고민을 원래 의미대로 보존한다.
블로그 본문은 사용자 본인의 시점으로 작성·편집한다. 전달된 고민·판단·이해의 변화를 본인의 서술로 연결하고, “사용자가”, “전달받은 Blog Context”, “이번 원고에서는” 같은 편집자 시점의 표현은 본문에 넣지 않는다. 본인 시점으로 바꾸더라도 실제로 하지 않은 경험·판단·검증을 만들지 않으며, AI 도움과 근거의 범위는 보존한다.
동료에게 자신의 판단 과정을 설명하는 톤으로 작성한다. 낯선 용어는 처음 등장할 때 짧게 설명하고, 개념 설명을 사용자가 왜 그렇게 이해하거나 판단했는지에 연결한다. 필요한 예시와 도식에는 읽는 방법을 덧붙인다. 실제 경험·검증 결과·남은 한계를 구분하며, 모든 글에 동일한 서사 구조를 강제하지 않는다.
사용자에게 없었던 실패·감정·의견·의사결정·수치·성과를 창조하지 않는다. 시니어 역할 연출과 과장된 표현을 피한다.
프로젝트에서 확인한 사실과 일반 개념·외부 사례를 구분한다. 외부 기술 개념은 필요한 근거를 확인하고 기존 Context와 충돌하는지 검토한다.
기술 사실이 부족하면 원자료를 확인하거나 cover-challenge에 물을 질문을 정리한다. 미확인 결과를 정상·성공으로 채우지 않는다.
사용자의 지식·구술 시험을 글쓰기·발행의 게이트로 요구하지 않는다.
한국어로 작성하고 필요한 기술 용어에 맥락 설명을 붙인다. 기술 용어마다 기계적으로 비유·영어 병기를 강제하지 않는다.
주제에 맞는 문제·원인·대안·trade-off·검증·한계를 서술한다. 모든 글에 고정된 단계 구조를 강제하지 않는다.
콘솔 캡처 이미지를 새 원고에 삽입하지 않는다. 복잡한 구조·흐름에는 실제 사실에 맞는 Mermaid를 활용한다.
SRE·FinOps·보안·커리어 관점은 실제 Context와 관련된 경우에 포함하며 Evidence 밖의 운영 경험을 만들어내지 않는다.
본문 작성 절차는 .codex/skills/blog-writing/SKILL.md를 따른다.

## 학습 맥락과 성과 표현
AI 도움 수준과 문제 난이도가 전달되면 글의 주장·성과 표현에 반영한다. AI 지원 결과를 사용자의 독립적 수행으로 과장하지 않는다.
Independent Thinking과 Evidence Literacy를 근거와 서술에 반영한다. 장기 인출·전이·자신감 비교·성장 검토는 튜터의 비차단 피드백이다. 전달된 관련 Insight를 보존하되 블로그가 직접 시험하거나 성장 여부를 판정하지 않는다.
Record 완료나 학습 시험 통과를 글쓰기·발행의 조건으로 요구하지 않는다.
